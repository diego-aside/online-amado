# 온라인 아마도 (Online Amado)

중앙대 후문 요리주점 '아마도'(서울 동작구 흑석로 10)를 재현한 온라인 술집 월드.
친구들과 같은 테이블에 앉아 음식을 주문하고, 술을 가져다 마시며, 취기와 허기까지 공유하는 멀티플레이 공간.

> 비공식 팬메이드 재현입니다. 사진 속 인물이나 사장님을 특정하지 않으며,
> 사장님 NPC는 리뷰 언급에 기반한 캐릭터입니다.
> 영업시간·전화번호·현재 가격은 가게에 직접 확인하세요.

## 구성

- `index.html` / `style.css` / `main.js` — 정적 사이트 (Three.js r170 + CSS3DRenderer + Supabase Realtime + PeerJS + YouTube IFrame API)
- `menu.json` — 메뉴·가격 (출처: 2026-09-10 네이버 플레이스 메뉴판, 2026-11-13 라이브 확인)
- `VERIFY.md` — 빌드 검증 기록

사장님 대사·입장 인사 문구는 `main.js` 상단의 `OWNER_LINES` / `GREETING` 상수에서 관리합니다.

## 흐름 (v11c 최종)

1. **입장** — 닉네임은 항상 빈칸으로 시작하고, 정하면 사장님이 먼저 맞이하고(혼자면 "혼자 오셨네요?", 여럿이면 "아미고들"), 잠시 뒤 인사 선택지 3개("안녕하세요!" / "오늘도 왔어요!" / "처음 왔어요!")가 한 번 뜹니다. 고르면 사장님이 답인사를 합니다(20초 지나면 자동으로 사라짐, X로 닫기 가능).
2. **테이블 앉기 (로비 없음)** — 별도 로비 화면·테이블 목록·생성/합류 폼이 없습니다. 3D 테이블이나 의자를 직접 누르면 **앉기 다이얼로그**가 뜹니다(테이블 번호 · 현재 인원 예: 2/4명 · 비밀번호 입력란 · [앉기] · 닫기). 테이블 위 `테이블 N · 인원/4 🔒` 이름표를 눌러도 같은 앉기 다이얼로그가 열립니다(입장 인사는 선택 사항).
   - **빈 테이블(처음 앉는 사람)**: 비밀번호는 선택입니다. 숫자 4자리를 넣으면 그 테이블의 비밀번호가 되고, 비워두면 공개 테이블입니다. 처음 앉은 사람이 테이블을 지킵니다(keeper).
   - **사람이 있는 테이블**: 비밀번호가 설정돼 있으면 4자리를 입력해야 앉을 수 있고(틀리면 거부, 3회 틀리면 1분 잠김), 공개 테이블이면 입력 없이 바로 앉습니다. 비밀번호 여부는 디렉토리 채널의 `locked` 플래그로 판단합니다.
3. **앉으면** — 오른쪽 패널(메뉴판 / 채팅 / 가게 정보)이 자동으로 열리고, 일어서면 닫힙니다. 헤더의 `—`로 최소화하면 `☰ 메뉴` 알약 버튼만 남습니다.
4. **음식** — 메뉴판에서 담으면 *주문(ordered)* 상태가 되고, 15~25초 뒤 사장님이 서빙합니다(첫 음식 주문 시 알새우칩 서비스, 4입). 서빙되면 채팅 탭 상단 **테이블 위** 목록, **계산서**, 3D 테이블 위 접시에 나타나고, 서빙 멘트는 모든 탭이 같은 문구입니다(서비스 항목은 알새우칩).
5. **술** — 메뉴판에서 주문하지 않습니다. 서쪽 벽의 **술 냉장고**(3D·이름표 클릭, 또는 메뉴판 드링크 탭의 "🧊 술 냉장고 열기")를 누르면 "가는 중…" 토스트와 함께 통행로를 따라 걸어가고, 13종 중 하나를 고르면 자리로 돌아오고, 테이블 위 목록과 계산서에 자동으로 올라갑니다. 테이블에 앉은 사람만 쓸 수 있습니다.
6. **먹기/마시기** — 테이블 위 목록·계산서·3D 접시 어디서든, 테이블에 앉은 누구든 누를 수 있고 효과는 누른 사람에게만 적용됩니다. 음식 1개 = 4입(먹기 1회: 취기·허기가 내려감, 남은 입은 n/4 와 dots 로 표시). 술은 **모금 단위**입니다 — 병 술 1병은 서빙될 때 6~8모금 중 랜덤(서빙을 확정한 쪽이 정해 모든 탭에 공유, 화면에는 숫자·dots 를 **표시하지 않음**), 잔 술 1잔 = 3모금. 마시기 1회 = 1모금. 병은 다 마시면 사라지지 않고 **빈병**(옆으로 눕고 옅은 색)으로 테이블에 남으며 마시기 버튼이 없어지고, 자리에서 일어나면 정리됩니다. 잔 술은 3모금 뒤 사라집니다. 주문만으로는 취하지 않습니다.
7. **허기** — 0(배부름)~5(배고파 죽겠어요). 입장 시 2, 5분마다 +1(HUD에 "배고플수록 많이 켜져요" 안내). 4 이상이면 사장님이 음식을 권하고, 이때 술을 마시면 모금당 취기가 +0.75 오릅니다(빈속, 평소 +0.5). 물 마시기·술 마시기는 허기에 영향이 없습니다.
8. **취기** — 0~5단계 동기화(물 −1, 화장실 −1, 안주 건네기 −0.5). 레벨 5는 무지개 토 🌈(60초 쿨다운).
9. 앉는 순간 줌형 격자 화면 — PeerJS 화상(카메라·마이크 기본 OFF), 테이블 공유 장바구니 + "내가 쏜다".

## HUD 게이지

취기(🍶)·허기(🍖)는 숫자 없이 **이모지 5칸**으로 표시합니다. 채워진 칸 = 현재 레벨 수(선명), 나머지 칸은 같은 이모지를 흐리게(opacity 0.25). 라벨('취기'·'허기')과 단계 문구는 그대로이고, 먹기·마시기 토스트와 버튼 title 도 수치 없이 말로만 안내합니다. 내부 수치 로직(레벨 0~5, 마시기 모금당 +0.5·빈속 +0.75·무알코올 +0, 먹기 −0.5·허기 −1)은 표시와 별개로 유지됩니다. 모든 UI 모서리는 12px(`--r`)로 통일(아바타·파티클 같은 원형 제외).

## 3D 음식·음료 모양 (v11b)

접시 위 해시 랜덤 색 공은 없앴습니다. `main.js` 의 `FOOD_LOOK` 테이블이 메뉴 itemId 별로 접시/그릇 + 1~7개의 간단한 도형(돔·박스·원기둥·공)으로 대략의 느낌만 냅니다(예: 뽀끔밥 = 그릇 + 볶음밥 돔 + 고기 조각, 떡볶이 = 소스 돔 + 흰 떡, 두부김치 = 두부 큐브 + 김치 조각). 없는 itemId 는 베이지 돔 폴백. 먹을수록 음식 조각 전체 그룹이 함께 줄어듭니다. 병은 원기둥 병 + FRIDGE 에 정의된 실제 술 색, 잔은 투명 컵 + 내용물 색(생맥주 거품, 하이볼은 키 큰 잔, 콜라·제로 짙은 갈색, 사이다 투명 연한색). 메뉴판 항목 앞에는 대표 색 작은 점(`.dot`)이 붙습니다.

## 빔 프로젝터 + 유튜브 스크린 (v11c)

남쪽 통유리 벽면(입구 문과 Amado 간판 사이)에 천장에서 내려오는 화이트 스크린(2.4m × 1.35m)이 있고, 그 앞 천장에 빔 프로젝터가 달려 있습니다. 켜져 있으면 빛줄기가 보이고 스크린에 유튜브가 뜨며, 꺼져 있으면 스크린이 하얗고 빛줄기가 없습니다. 방 전체가 같은 화면을 보는 공용 시설이고, 앉아 있지 않아도 쓸 수 있습니다.

- **조작**: 3D 프로젝터(또는 `📽️ 프로젝터` 이름표)를 누르면 전원, 스크린을 누르거나 하단 `📽️ 스크린` 버튼을 누르면 패널(전원 · 소리 · 다른 영상 · 유튜브 링크 입력)이 열립니다. 자동재생은 음소거라 `🔇 소리 켜기`를 눌러야 소리가 납니다.
- **기본 상영**: 입장하거나 켤 때 두 프로그램 중 하나를 랜덤으로 틀고, 끝나면 다시 랜덤. ① 중앙사랑 플레이리스트(영상 1개) ② UBS '일인용 식당'(예고편 → EP.1 마라 조개볶음 → EP.2 밀푀유나베 → EP.3 돼지고기 김치찜, 끝나면 자동으로 다음 영상). `🔀 다른 영상`은 프로그램을 바꿉니다(시리즈는 예고편부터).
- **링크 변경**: 유튜브 URL(watch · youtu.be · shorts · live · embed)을 붙여넣으면 프로그램을 멈추고 그 영상만 틀며, 끝나면 다시 두 프로그램 중 랜덤. 유튜브 링크가 아니면 "유튜브 링크가 아니에요".
- **동기화**: 채널 `amado-screen`(이벤트 `screen` · `screen-req`)에 전원·프로그램·영상 ID 만 실립니다(테이블 정보·채팅 없음). 바꾼 사람이 keeper 로서 알리고, 새로 들어온 사람은 현재 상태를 받습니다. 재생 시각(초)은 맞추지 않고 같은 영상·순서만 공유합니다.
- **레이어**: WebGL 캔버스 → CSS3D iframe 레이어(캔버스 위, 클릭 통과) → 이름표 → HUD 순입니다. 영상 로드에 실패하면 스크린에 "유튜브 링크를 붙여넣어 영상을 틀어요"가 표시됩니다.
- 미확인: 3D 모양·실제 유튜브 재생·2인 동시 접속은 이 환경에서 확인하지 못했습니다(`VERIFY.md` 참고).

## v11 추가 동작

- 상단 배지: 끊김 3초 미만은 표시 없음, 3초 이상이면 "재연결 중". 인원수는 로비 presence 단일 출처
- 같은 테이블 아바타 위치는 테이블 presence 의 자리(seat)로 모든 탭이 같게 그림. 일어서면 "자리로 돌아가기" 버튼
- 카메라: 초점 이동 범위 제한 + "🎥 시점 초기화" 버튼
- 격자 🍺=취기 단계, 🍽️=허기 단계(0~5). 사장님 음식 추천은 5분에 1회 이하·채팅이 활발하면 생략, 혼자 앉으면 가끔 반응

## 룸 레이아웃 (v10 최종)

주문대를 기준으로 세로로 긴 공간(7.2m × 14m). 위쪽(먼 쪽 끝)에 **주문대(사장님은 카운터 안)** 가 있고, **술 냉장고는 서쪽(왼쪽) 벽**에 붙어 문이 방 안쪽(동쪽)을 보고, **오른쪽 벽에 화장실 문**이 있습니다. 아래쪽(가까운 쪽 끝)은 **왼쪽에 통유리 접이문 입구**(스폰은 그 앞, 카운터를 바라봄), **오른쪽 벽에 벽걸이 에어컨**입니다. 테이블 6개(각 4석)는 2열 × 3행이며 테이블 긴 방향이 방 길이(z)와 같고 좌석은 테이블 양옆에 2개씩, 가운데 통로 2.4m는 비어 있습니다. 카메라는 입구 뒤쪽 위에서 카운터 쪽을 봅니다.

통유리 밖에는 인도 + 아스팔트 1차선 도로(중앙 점선)가 +x 방향으로 내려가는 **내리막길**로 이어지고, 배낭 색만 다른 학생 3명이 제자리 걷기 애니메이션과 함께 천천히 내려갔다가 위쪽으로 되돌아오는 루프로 오갑니다(기본 도형만 사용, 충돌 없음).

## 실시간 채널 (Supabase Realtime, 접두사 `amado-`)

- `amado-lobby` — 아바타 위치·자리(presence). 채팅·주문·취기·허기는 싣지 않음
- `amado-tables` — **테이블 디렉토리**(broadcast). 테이블 keeper(가장 먼저 앉은 사람)가 `{tid, count, seats, locked}` 를 만들 때·인원이 바뀔 때·5초마다 알리고, 새로 들어온 클라이언트는 `tables-req` 로 현재 상태를 받아옵니다. 앉은 사람이 로비 presence 에서 빠져도 테이블 점유가 사라지지 않게 하는 채널이며 코드·이름·채팅은 싣지 않음
- `amado-door-N` — 입장 비밀번호 확인(노크/승인). 비밀번호 없는 공개 테이블은 입력 없이 승인, 있는 테이블은 nonce+해시 증명으로만 확인(평문 미전송)
- `amado-screen` — 프로젝터 스크린(방 전체 공용). `screen`(상태 `{on, prog, idx, vid, seq, by}`) · `screen-req`(새로 들어온 사람의 현재 상태 요청)
- `amado-table-N` — 채팅·주문·서빙(`serve`)·먹기(`eat`)·마시기(`drink`)·취기·허기·건배·무지개 토

`locked` 는 비밀번호 설정 여부일 뿐 비밀번호 자체는 싣지 않습니다. 로비 presence 는 아바타·접속 인원수(상단 배지)에만 쓰고, 테이블 고르기 UI 는 없습니다.

로비·디렉토리 채널은 연결이 끊기면 1→2→4→8초… 최대 30초 간격으로 계속 재구독하고, 재구독하면 presence 를 다시 등록합니다.

## 로컬 실행

```bash
python3 -m http.server 8000
# http://localhost:8000 접속
```

멀티플레이는 Supabase Realtime을 쓰며, 연결 실패 시 1인 모드로도 동작합니다.
